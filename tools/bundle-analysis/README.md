# Bundle analysis

`node tools/bundle-analysis/gz-by-source.mjs` (after `./gradlew :web:jsBrowserProductionWebpack`) prints the production bundle's size by origin: each npm package, the Kotlin code and its runtime ("kotlin/other"), and code the source map cannot place ("unmapped", mostly the Kotlin standard library). Measured 2026-11-03 at 207.6 KB gzipped: Kotlin and runtime about 134 KB, unmapped about 36 KB, noble 37 KB (curves 20, hashes 10, ciphers 7).

Why this is not trimmed further: Kotlin's dead-code removal already drops unreachable code (Shamir, export verifier, image policy and others are absent); the remainder is the program itself plus kotlinx-serialization, coroutines, kotlinx-html and the standard library. Terser is set to three passes in `web/webpack.config.d/minify.js` (-2.6 KB). `web/webpack.config.d/noble-shims.js` (2026-11-03) writes a one-line ES module per noble package that re-exports only the names we call and aliases the package path to it, so webpack drops the rest of noble: 242.0 to 228.2 KB gzipped. Keep its list in step with the `@file:JsModule` externals; a new module without an entry stops the build.

Measured 2026-11-04 at 242.8 KB gzipped (by `gz-by-source.mjs`, now grouped by our packages and library files): Kotlin runtime and standard library helpers about 59 KB (`NATIVE_IMPLEMENTATIONS.kt`: Long arithmetic, collections, strings), code the map cannot place about 43 KB, other library code (coroutines, html, serialization) about 25 KB plus about 12 KB of kotlinx-serialization JSON, our own packages about 65 KB (event 19, web 18, app 15, sync 7), noble 24 KB. Terser with `unsafe`, `toplevel` compress and mangle saved only 0.9 KB and was not kept. Real savings now need structural work (a hand-written JSON reader for the few API shapes, about 10 KB; fewer kotlinx-html builders) or a decision to raise the budget.
